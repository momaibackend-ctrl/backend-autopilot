# ADR 008: Dedicated sandbox identity boundary

Status: accepted. Provider identity discovery and provisioning require explicit confirmation that the active account is isolated from personal and production resources. GitHub registration additionally requires the expected login string and an exact active-identity match. Existing accounts are preserved: authorization uses official web login followed by explicit `gh auth switch`, never `gh auth logout`. A pre-existing repository may be adopted only through a separate exact `owner/name` confirmation, private-repository check, `ADMIN` permission check, owner match, and project-scoped Resource Registry entry. Supabase adoption requires an exact expected project ref and rejects an account containing any other project; Windows Supabase CLI credentials use a global Credential Manager target, so filesystem `SUPABASE_HOME` is metadata isolation rather than an independent account keyring. After confirmation the agent performs setup autonomously. Login, OAuth, 2FA, CAPTCHA, billing and legal consent remain human actions.
